Temuan audit

1

Radar level terputus / 0 V terbaca "tangki penuh" → pompa ON kering

Level_Sensor.cpp:30-40 · ModeOtomatis.cpp:17-20

Tinggi

Skenario. Konverter 4-20 mA → 0-3 V: 0 V (kabel putus / ADC mengambang) = 4 mA, dan 4 mA dengan SENSOR_INVERTED=true dihitung level 100 % → jarak 0 cm → tinggiAir = 100 ≥ 20 → pompaOn(). Berbeda dengan TUNGGU_AIR yang memeriksa jarak > 0, AUTO_BACA_LEVEL tidak memeriksa apa pun.

Saran. Tolak jarak ≤ blind-zone sensor (mis. < 5 cm) dan nilai ADC di luar rentang sebagai FAULT → jangan nyalakan pompa, tampilkan error.

2

HTTP blocking menunda pembacaan float switch saat pompa ON → risiko meluap

Network.cpp:37-38 · main.cpp:133-146, 618 · ModeOtomatis.cpp:30-44

Tinggi

Skenario. Tiap loop() memanggil cekOverrideManualDariWeb() (1 s) dan cobaKirimUlangBuffer() (tiap iterasi). Saat jaringan buruk satu request bisa menahan loop hingga 8 + 12 s. Selama AUTO_ISI_CHAMBER float switch — satu-satunya pelindung overflow — tidak dibaca.

Saran. Baca float di luar jalur HTTP (task FreeRTOS / ISR) dan matikan pompa langsung dari sana; atau jangan lakukan HTTP selama pompa ON. Beri batas waktu HTTP jauh lebih kecil di state ini.

3

Interlock pompa manual dimatikan & tidak ada batas waktu jalan

Config.h:55 · ModeManual.cpp:125, 143-149

Tinggi

Skenario. INTERLOCK_POMPA_MANUAL = 0, jadi perintah pump_cmd="jalan" dari web dieksekusi walau chamber penuh atau kering, dan terus menyala sampai ada perintah "berhenti". Cabang "Aman? → Tolak" pada flowchart PDF tidak berfungsi.

Saran. Aktifkan interlock begitu float terpasang, tambah batas waktu maks pompa manual (mis. 5 mnt) dan kondisi level minimum.

4

Pompa/valve terbawa dari manual ke otomatis

ModeManual.cpp:56-61 · ModeOtomatis.cpp:20-26

Tinggi

Skenario. Saat web mengembalikan mode ke "otomatis", state langsung A_BACA_MODE tanpa pompaOff()/valveTutup(). Jika level < 20 cm, jalur ke A_CEK_STOP berulang sementara pompa yang dinyalakan operator tetap ON (kering). (Aktif hanya jika FORCE_MODE_MANUAL = 0.)

Saran. Panggil pompaOff() dan valveTutup() pada transisi manual → otomatis (dan sebaliknya) sebelum mengubah state.

5

AUTO_TUNGGU_KOSONG tanpa timeout; float tak terpasang = HIGH

ModeOtomatis.cpp:94-99 · main.cpp:105-113, 343

Tinggi

Skenario. Float memakai INPUT_PULLUP: kabel lepas/putus terbaca HIGH. Di AUTO_ISI_CHAMBER itu berarti pompa langsung OFF dan siklus lanjut dengan chamber kosong; di AUTO_TUNGGU_KOSONG siklus macet selamanya dengan valve terbuka. Satu-satunya jalan keluar adalah override dari web.

Saran. Tambah timeout di TUNGGU_KOSONG (lalu paksa valve tutup + error), dan deteksi float "selalu HIGH" (mis. HIGH tanpa level naik) sebagai fault.

6

Return value valveBuka()/valveTutup() diabaikan di siklus otomatis

ModeOtomatis.cpp:85, 96-97 · Valve_Controller.cpp:35-39, 49-53

Sedang

Skenario. Debounce 3 s menolak perintah jika aksi terakhir < 3 s (mengembalikan false). Siklus otomatis tetap melanjutkan state, sehingga valve bisa tetap terbuka (atau tidak pernah terbuka) tanpa dicoba ulang; siklus berikut mengisi chamber sementara drain terbuka.

Saran. Ulangi sampai true (dengan batas) sebelum pindah state; laporkan error jika gagal.

7

Retry pompa tanpa batas setelah timeout 5 menit

ModeOtomatis.cpp:38-42

Sedang

Skenario. Timeout → pompaOff + tampilkanError → A_CEK_STOP → AUTO_BACA_LEVEL → pompaOn lagi. Tidak ada penghitung/lockout, sehingga selang tersumbat atau pompa rusak akan dicoba tanpa akhir.

Saran. Hitung timeout beruntun; setelah N kali masuk state FAULT (pompa terkunci OFF) sampai operator reset dari web.

8

Dengan konfigurasi sekarang tidak ada data pH/TSS yang terkirim otomatis

Config.h:27 · main.cpp:595-599 · ModeManual.cpp:9-16

Sedang

Skenario. FORCE_MODE_MANUAL = 1 mengunci mode manual, sedangkan mode manual sengaja tidak membaca/mengirim pH & TSS. Jadi seluruh cabang otomatis di flowchart PDF (dan cabang "pH&TSS → Kirim" di manual) tidak berjalan; hanya perintah serial "K" yang mengirim data.

Saran. Pastikan memang disengaja untuk pengujian; kembalikan ke 0 sebelum operasi nyata atau jalankan logging di task terpisah.

9

TSS dikirim tanpa validasi

main.cpp:681-706 · ModeOtomatis.cpp:63-82

Sedang

Skenario. Jika semua 5 sampel gagal (count = 0), avgRaw = 0 lalu calibrated = offset dan dikirim sebagai pembacaan sah; nilai negatif dipaksa 0. State VALIDASI hanya menguji pH.

Saran. Kembalikan status validitas dari bacaRataRataTSS() dan kirim tss=null / ulangi baca bila semua sampel gagal.

10

Buffer offline: data hilang, level & waktu salah

Network.cpp:131-132, 171-212

Sedang

Skenario. Ring buffer 20 slot menimpa data tertua tanpa pemberitahuan; hanya di RAM (hilang saat reboot/brownout). Tidak ada timestamp, dan kirimDataKeAPI() membaca ulang readTankSensor() saat kirim ulang, sehingga water_level pada data buffer = level saat kirim, bukan saat ukur.

Saran. Simpan water_level dan timestamp ke dalam DataSample; beri indikator overflow; pertimbangkan NVS bila data penting.

11

Tidak ada failsafe saat komunikasi putus; gagal-fetch jatuh ke OTOMATIS

main.cpp:598 · Network.cpp:264-267 · ModeManual.cpp:48, 143-149

Sedang

Skenario. Fetch gagal → modeOtomatis = true (fail-open) walau operator menetapkan manual. Di mode manual, jika WiFi putus saat pump_cmd="jalan", perintah terakhir tetap berlaku dan pompa menyala terus (tidak ada dead-man).

Saran. Pertahankan mode terakhir yang diketahui saat fetch gagal; matikan pompa jika tidak ada polling sukses > X detik.

12

Kanal kontrol tanpa autentikasi; kredensial ada di source

Network.cpp:7-8 · Config.h:20-21

Sedang

Skenario. Publishable key tertanam di firmware dan dipakai untuk membaca perintah serta menulis status. Siapa pun yang memegang key dapat menulis system_control jika RLS mengizinkan. Password WiFi tertulis di Config.h (file ini berstatus modified di git).

Saran. Periksa RLS system_control (tulis hanya user dashboard terautentikasi), pindahkan kredensial ke file lokal yang di-gitignore.

13

Jalur mati: STOPPED, TUNGGU_AIR, TUNGGU_FLOAT_SWITCH, state M_*

main.cpp:660-663 · Modes.h:14-27 · ModeOtomatis.cpp:5-14

Rendah

Skenario. permintaanBerhenti() = false (TODO), jadi STOPPED dan terminal "Selesai" di PDF tidak terjangkau — tidak ada emergency stop. TUNGGU_AIR/TUNGGU_FLOAT_SWITCH tidak punya transisi masuk (dan TUNGGU_AIR memakai logika jarak yang berbeda dari BACA_LEVEL). M_CEK_INTERLOCK, M_JALANKAN_PERINTAH, M_KIRIM_DATA tidak pernah dipakai.

Saran. Implementasikan flag stop dari Supabase atau hapus state mati supaya flowchart = kode.

14

Indikator error menyangkut; status error pH hanya dicetak

main.cpp:576, 654-658 · Network.cpp:161-169

Rendah

Skenario. LED error hanya dipadamkan di CEK_KONEKSI sehingga error siklus (timeout, pH invalid) tetap menyala setelah pulih. kirimStatusErrorKeAPI() hanya mencetak ke serial dan selalu true — dashboard tidak mengetahui kegagalan pH.

Saran. Padamkan LED saat siklus berhasil; kirim status error ke tabel yang dilihat dashboard.
